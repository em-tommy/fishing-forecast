# 釣行ダッシュボード（上越直江津・東京湾）

上越直江津の**出船候補日**を根拠データつきで絞り込み、東京湾5か所の陸っぱりの気象・潮汐を1画面で比べるための静的サイト。
Windy で毎回やっていた「複数モデルを見比べて穏やかな日を探す」作業の置き換えを目的にしている。

- **上越 出船タブ** — 2日以上つづく凪ウィンドウを上位表示。選んだ時間帯の最悪値で ◎○△× 判定。
  波高が出ている期間の単日候補も別枠で必ず出す（8日先の「風だけの連続○」より、波高まで揃った単日のほうが確実に動けるため）
- **東京湾 陸っぱりタブ** — 若洲・東扇島西・ふれーゆ裏・大黒ふ頭・本牧を同じ日付で横並び比較
- **設定タブ** — しきい値をスライダーで調整（ブラウザに保存）。データの限界もここに明記
- **使い方タブ** — アプリ内マニュアル。しきい値表・バッジ表・時間帯表は判定エンジンの定義から生成するので、
  ルールを変えれば説明も自動で追従する（手書きだとマニュアルだけ古くなるため）

ビルド不要。`index.html` をブラウザで開けばそのまま動く（潮汐データは `<script>` で同梱しているので `file://` でも可）。

## データ元

| 種類 | 提供元 | 範囲 |
|---|---|---|
| 風・突風・風向 | [Open-Meteo Forecast API](https://open-meteo.com/) — ECMWF IFS / NCEP GFS / DWD ICON / 気象庁 の4モデル | **16日先** |
| 天気・気温・降水確率 | 同上（best match） | 16日先 |
| 波高・うねり・周期 | [Open-Meteo Marine API](https://open-meteo.com/en/docs/marine-weather-api) | **8日先まで** |
| 潮汐（毎時潮位・満干潮） | [気象庁 潮位表](https://www.data.jma.go.jp/kaiyou/db/tide/suisan/) 直江津(T3) / 東京(TK) / 横浜(QS) | 年間（同梱） |
| **公式予報（第2の意見）** | [気象庁 府県天気予報](https://www.jma.go.jp/bosai/forecast/) 天気・**海上の風**・**沿岸の波**・降水確率・**確度A/B/C**・気象台の解説文 | 風波は3日先 / 週間は7日先 |
| **Yahoo!天気（第3の意見）** | [Yahoo!天気](https://weather.yahoo.co.jp/) 上越市・津南町の週間予報（日本気象協会） 天気・気温・降水確率 | 明後日から6日分 |

Open-Meteo は API キー不要・非商用無料。潮汐は気象庁のテキストをビルド時に取得して同梱する（ブラウザから直接は取れないため）。

### なぜ気象庁と Yahoo天気も併記するのか

現地の農業関係者から「Yahoo天気の2週間予報が一番当たる」という評価があった。

**Yahoo天気は気象庁の中継ではない。** 実測で比べると値が一致しない（2026-07-28 発表時点）。

| 日付 | 気象庁 確度 | Yahoo 確度 | 気象庁 降水 | Yahoo 降水 |
|---|---|---|---|---|
| 7/30 | — | A | **80%** | **50%** |
| 7/31 | **C** | **A** | 70% | 60% |
| 8/1 | **B** | **C** | 30% | 40% |
| 8/2〜8/4 | A | A | 20% | 10% |

[日本気象協会](https://www.jwa.or.jp/case/01/)の統計補正が入っているためで、両者が割れている日は
素直に「予報が固まっていない日」と見るのが正しい。そこで3つ（モデル / 気象庁 / Yahoo）を並べ、
**食い違いを差のまま提示する**。

**Yahoo天気から取れるもの・取れないもの**（実測で確認）:

- Webページ … 明後日から6日分の天気・最高最低気温・降水確率。**値はスマホアプリと完全一致する**
- アプリのみ … **信頼度A〜Cと7〜15日目**。Webページには存在せず、非公開APIの中にしかないので取得しない。
  確度が要る用途には気象庁の公式値（A/B/C・7日）を出している

Yahoo には予報の公開APIが無い（YOLPの気象情報APIは前後1時間の降水強度のみ）ので、
`tools/Fetch-Yahoo.ps1` が公開ページの週間予報テーブルを読む。ページ2枚を1日4回、
ツール名を名乗る User-Agent で取得する。**間隔を詰めないこと。**

気象庁が効くのは全球モデルが苦手な2点。

- **沿岸の波** — 予報区ごとの実務的な波高予報。25km格子の全球波浪モデルより岸の実態に近い
- **海上の風** — 「海上では南西の風強く」のように陸と海を分けて書かれる

判定そのものは書き換えず、食い違いを提示する。実際、2026-07-28 は当アプリのモデル値
0.72m に対し気象庁は「０．５メートル 後 １．５メートル」で、警告が出る。検出条件は
気象庁の波が 0.3m 以上高い / 降水確率が30ポイント以上違う（気象庁対モデル・Yahoo対モデル・気象庁対Yahoo）/
気象庁の確度が C なのにモデルは一致、の5つ。

気象庁 bosai の JSON は公式APIとして提供されているものではないので、取得に失敗しても本体の判定は止めない。

### 知っておくべき限界

- **波高は8日先までしか存在しない。** 9日目以降は風だけの暫定判定になり、`波高データなし` バッジが付く。
  この期間は ◎ を付けず ○ 止まりにし、候補の並び順でも波浪データのある窓を先に出している。
  「制約が1つ少ないから上位に来ただけ」の日を選んでしまわないための仕様。
- 東京湾内の波高は約25km格子の推計値。実際の岸壁の状況とは差が出る。
- 潮汐は天文潮位。気圧・風による偏差は含まない。
- 直江津は日本海側で潮差が30cm前後しかない。大潮でも東京湾のようには動かないので、
  潮回りの名前ではなく併記している**実潮差(cm)** を見ること。

## 判定ロジック

`assets/rating.js`（純関数のみ・DOM に触らない）に集約している。

**判定時間帯**は画面上部で **朝マヅメ / 昼間 / 夕マヅメ / 終日** から選ぶ。上越タブと東京湾タブで別々に保存されるので、
「上越は朝、東京湾のアジは夕方」といった使い分けができる。その窓の**最悪値**で決める（平均だと一瞬の突風やうねりを見落とすため）。

境目は固定時刻ではなく日の出・日の入から決まる。固定時刻だと季節でずれるため。

| 時間帯 | 範囲 | 夏の例(日の出5:00 日の入19:00) | 冬の例(7:00 / 16:30) |
|---|---|---|---|
| 朝マヅメ | 日の出−1h 〜 +4h | 04:00〜09:00 | 06:00〜11:00 |
| 昼間 | 朝マヅメの終わり 〜 夕マヅメの始まり | 09:00〜15:00 | 11:00〜12:30 |
| 夕マヅメ | 日の入−4h 〜 +1h | 15:00〜20:00 | 12:30〜17:30 |
| 終日 | 朝の開始 〜 夕の終了 | 04:00〜20:00 | 06:00〜17:30 |

昼間を独立に定義せず「朝と夕の隙間」とすることで、隙間も重複も生じない。日照が短く朝と夕が重なる日は南中±1時間にフォールバックする。

| 判定 | 平均風速 | 最大瞬間 | 有義波高 |
|---|---|---|---|
| ◎ 出船適 | ≤ 4.0 m/s | ≤ 7.0 m/s | ≤ 0.30 m |
| ○ 出船可 | ≤ 5.0 | ≤ 8.0 | ≤ 0.40 |
| △ 要注意 | ≤ 6.0 | ≤ 9.0 | ≤ 0.50 |
| × 出船不可 | それ超 | それ超 | それ超 |

○ は ◎ と △ の中点として自動的に決まる。しきい値は設定タブから変更可。

補正ルール:

- **雷**（WMO 95/96/99）が判定窓にかかる日は、風も波も穏やかでも **×**。小型艇に逃げ場がないため
- **強い雨・雪**（65/67/75/82/86）は1段階格下げ
- **長周期うねり**（周期 ≥ 8s かつ うねり高 ≥ 0.20m）は1段階格下げ。波高の数字以上に3m艇は揺れる
- **吹き付け風**（WNW 292.5°〜ENE 67.5°、風速3m/s以上）は1段階格下げ。
  直江津の海岸は北〜北北東向きで、日本海の北西季節風が最も危ない。陸っぱり（東京湾）には適用しない
- **沖出し（陸風）**（ESE 112.5°〜WSW 247.5°）は警告のみで判定は下げない
- **午後の吹き上がり**（12〜16時が朝より3m/s以上強い）は「早上がり推奨」警告。朝マヅメを選んだときのみ
- **波高データなし**の日は上限を ○ に制限

**モデル一致度**は4モデルの風速の標準偏差の平均。`< 1.0 m/s` = 高 / `< 2.0` = 中 / それ以上 = 低。
代表値には中央値を使う（`wind_gusts_10m` は気象庁モデルが常に null を返すので、欠損を除いて計算している）。

## セットアップ

### 1. 潮汐データを生成する

```powershell
powershell -ExecutionPolicy Bypass -File tools\Build-Tide.ps1 -Year 2026
```

`data/tide-2026.js` を生成し、`index.html` と `tests.html` の `<script>` タグも自動で同期する。
翌年分が気象庁から公表されたら `-Year 2027` でもう一度実行すれば、両方が読み込まれるようになる。

このスクリプトは意図的に **ASCII のみ**で書いてある。Windows PowerShell 5.1 は BOM 無し UTF-8 の `.ps1` を
システムの ANSI コードページとして読むため、日本語を入れると壊れる。地点の表示名は `assets/tide.js` 側にある。

Linux / macOS では `pwsh -File tools/Build-Tide.ps1 -Year 2026`。

### 2. ローカルで開く

`index.html` をダブルクリックするだけでも動く。HTTP で確認したい場合:

```powershell
python -m http.server 8765 --directory .
# http://localhost:8765/
```

### 3. 公開する

`.github/workflows/pages.yml` が main への push で GitHub Pages に公開する。
リポジトリの Settings → Pages → Source を **GitHub Actions** にしておくこと。

Vultr の VPS に置く場合はディレクトリごと nginx の document root にコピーするだけでよい。
ビルド成果物はリポジトリの中身そのもの。

### 4. 潮汐データの自動更新

`.github/workflows/tide.yml` が毎月6日に走り、今年と来年の潮位表を取り直して差分があればコミットする。
気象庁が翌年分を出すのは年明けなので、それまでは `-AllowMissing` で静かにスキップされる。

`.github/workflows/yahoo.yml` が1日4回（JST 06:30 / 12:30 / 18:30 / 00:30）Yahoo天気の週間予報を取り直す。
手元で更新する場合は `powershell -ExecutionPolicy Bypass -File tools\Fetch-Yahoo.ps1`。

## テスト

`tests.html` をブラウザで開くと 170 件のアサーションが走り、上部に結果が出る。
判定エンジンの境界値・欠損処理・風向の循環計算・荒天ルール・連続窓の並び順・時間帯の切り出し・
気象庁の予報文の解釈（全角の波高文の数値化）と食い違い検出に加えて、
潮汐は**気象庁の公表値との突合**（横浜 2026-01-01 の満干潮）と、
**大潮 > 中潮 > 小潮の平均潮差**が実データで成立するか（＝月齢計算の裏取り）を確認している。

## 構成

```
index.html              画面の骨格
tests.html              テストランナー（ブラウザで開くだけ）
assets/style.css        配色・レイアウト。判定は色だけでなく記号を必ず併記
assets/tide.js          潮位表データの読み出し、潮回り・潮差・上げ下げ・補間
assets/rating.js        出船スコアリングと気象庁との突き合わせ（純関数。ここだけ読めば判定仕様が分かる）
assets/jma.js           気象庁の公式予報の取得と予報文の解釈
assets/yahoo.js         Yahoo!天気の週間予報の読み出し
assets/manual.js        「使い方」タブ（判定エンジンの定義から生成）
assets/app.js           データ取得・正規化・描画
data/tide-YYYY.js       生成物。直接編集しない
tools/Build-Tide.ps1    気象庁テキスト → data/tide-YYYY.js
tools/Fetch-Yahoo.ps1   Yahoo!天気の週間予報 → data/yahoo.js
```

気象データは `localStorage` に30分キャッシュする。取得に失敗したときは期限切れでもキャッシュを表示し、
ヘッダに「⚠ 取得失敗・キャッシュ表示」と出す（港で圏外のときに何も出ないより有用なため）。

### レート制限への対処

Open-Meteo は「変数 × 日数 × モデル」で重み付けしてレート制限する。6地点ぶんを一度に投げると 429 が返るので、

- モデル比較画面を持つ**直江津だけ4モデル**、東京湾の5か所は**3モデル**（ECMWF / GFS / 気象庁）に絞る。
  ICON ではなく GFS を残すのは、16日目まで値があるのが GFS だけで、外すと最終日が「データなし」になるため
- 同時実行は**2地点まで**に絞り、直江津を先に取る（制限に当たっても最重要の地点は揃う）
- 429 は 2.5 秒待って1度だけやり直す

最終的な出船可否は現地の海況と気象庁・海上保安庁の警報で判断すること。このアプリは候補日の絞り込み用。
